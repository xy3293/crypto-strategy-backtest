# 资金费率策略专项报告 (Funding-Rate Strategies)

本轮是项目最后一次找新策略：只测纯永续合约上的方向性资金费率策略。
**现货 + 做空永续的 Delta 中性套利不在本轮范围内**——本引擎没有现货腿，
测不了，特此说明。

## 1. 设计依据

资金费率是永续合约特有的收益来源：费率为正时多头付给空头，为负时反过来。
此前 12 个策略全周期都在净付资金费（买入持有甚至因此爆仓，ETH -$11,914.76、
SOL -$120,227.96）。本轮测试资金费能不能从成本项变成信号源或过滤器。

| 策略 | 规则 | 参数 |
|---|---|---|
| `funding_zscore_fade`（资金费率极端反向） | 资金费率 30 天滚动 z-score；z > +2.5 做空（多头拥挤），z < -2.5 做多；\|z\| < 0.5 平仓 | z_entry=2.5, z_exit=0.5, ATR(14)×2 止损, max_days=14 |
| `funding_extreme_threshold`（绝对阈值反向） | 费率 > +0.05%/8h 做空，< -0.05%/8h 做多；费率穿过 0 平仓 | high=+0.0005, low=-0.0005, ATR(14)×2 止损, max_days=14 |
| `funding_filtered_keltner`（资金费过滤的肯特纳） | 肯特纳突破进出场逻辑不变，只在资金费顺风时开新仓：做多仅当费率 ≤ +0.01%/8h，做空仅当费率 ≥ -0.01%/8h；已有仓位按原规则管理 | keltner 默认参数 (ema 35, atr 17, mult 2.0, stop 2.0) + long_max_funding=+0.0001, short_min_funding=-0.0001 |

参数依据：公开的资金费率逆势回测研究用 30 天基线、±2.6~2.85σ 阈值；
+0.05%/8h 被视为多头极度拥挤的信号。全部 4h、默认成本（$10,000、2x 杠杆、
手续费 0.05%/边、滑点 0.05%/边、资金费每 8h、每笔风险 1% ATR 止损）。

## 2. 实现说明

策略模块原本只能看到 K 线（`df` 只有合约 OHLC + mark OHLC），资金费率在
另一个独立的 DataFrame 里，只传给引擎结算用。本轮做了一个小改动：

- `backtest/data.py` 的 `load()` 在两个返回路径（缓存 / 新下载）里都给 `df`
  挂上 `funding_rate` 列：取每根 K 线开盘时刻之前最近一次 8h 结算的费率
  （`funding['rate'].reindex(df.index, method='ffill')`，首行缺失填 0.0）。
  前向填充只用已发生的结算事件，无前视偏差（Antigravity 已在真实 BTC
  数据上逐根核对）。
- `funding_zscore_fade` 的 z-score 用 180 根 K 线滚动均值/标准差（ddof=0，
  min_periods=90）。每个 8h 资金费事件恰好横跨两根 4h K 线，所以 180 根
  K 线 = 30 天 = 90 个不重复的资金费观测值；用总体标准差（ddof=0）时，
  每事件重复出现两次不影响均值与标准差（Antigravity 已在真实数据上
  验证该等价性）。
- `funding_filtered_keltner` 直接复用 `keltner_breakout.generate_signals`，
  只对 direction 列做掩码（不满足资金费条件时置 0），止损与出场列原样保留。
- `backtest/strategies/__init__.py` 注册三策略，策略总数 12 → 15。
- 测试：新增 `tests/test_funding_strategies.py`（每策略 5 项：多/空入场、
  多/空出场、前缀不变性）；`tests/test_engine.py` 的 candle fixture 加了
  `funding_rate: 0.0`，其前缀不变性测试随 NAMES 扩到 15 个策略自动扩展。
  pytest 70 → **88 passed**。
- 执行成本：Codex 第一次常规调用因沙箱缺 bwrap 失败，烧掉 29,089 tokens
  零产出；一次更窄的 `--dangerously-bypass-approvals-and-sandbox` 重试成功，
  22,093 tokens。无 quota / rate-limit 问题。Antigravity 全程审阅 + 跑回测，
  审阅结论 clean（无 bug、无前视、无需修改）。

## 3. 全周期结果（2021-01-01–2026-11-08，4h）

| 策略 | BTC 收益 / 夏普 / 回撤 / 笔数 / 均持仓 | ETH 收益 / 夏普 / 回撤 / 笔数 / 均持仓 | 资金费 BTC / ETH |
|---|---|---|---|
| `funding_zscore_fade` | -3.39% / -0.11 / -12.55% / 133 / 1.32d | -7.45% / -0.28 / -11.18% / 159 / 1.04d | +$194.25 / +$180.56 |
| `funding_extreme_threshold` | +2.94% / 0.12 / -8.41% / 39 / 5.47d | -19.98% / -0.66 / -21.17% / 56 / 4.52d | +$574.83 / +$545.63 |
| `funding_filtered_keltner` | **+61.56% / 0.68 / -12.50% / 256 / 4.09d** | **+55.46% / 0.66 / -15.79% / 241 / 4.17d** | -$356.13 / -$496.18 |
| `keltner_breakout`（对照） | +69.31% / 0.72 / -13.45% / 270 / 4.13d | +37.34% / 0.48 / -16.49% / 265 / 4.08d | -$772.21 / -$742.87 |

**Verdict：两个反向策略判死刑，一个过滤策略存活。**

- `funding_zscore_fade`：**DEAD**——两边都亏（BTC -3.39%，ETH -7.45%）。
  它确实赚到了资金费（两边合计 +$375），但平均持仓只有 1.0–1.3 天，
  逆势的价格亏损 + 摩擦完全盖过了资金费收入。
- `funding_extreme_threshold`：**DEAD**——BTC 微赚 +2.94%（仅 39 笔，样本极薄），
  ETH -19.98%（胜率仅 16.07%，盈亏比 0.46）。任一币种不赚钱即死刑，不调参、不重试。
- `funding_filtered_keltner`：**存活，进入验证**——两边都正，且 ETH 大幅优于
  未过滤的肯特纳（+55.46% vs +37.34%，夏普 0.66 vs 0.48）。

资金费过滤确实兑现了设计目标：四个币种的资金费拖累全部下降约 1/3–1/2
（BTC -$356 vs -$772，ETH -$496 vs -$743，SOL -$802 vs -$1,248，
BNB -$737 vs -$1,206）。但省下的资金费只在 ETH 上转化成了更高收益；
BTC、SOL、BNB 上过滤版收益反而低于未过滤版——过滤掉了一些本该赚钱的突破。

## 5. 结论

1. **纯资金费率反向策略行不通。** 两个反向策略都赚到了正资金费
   （zscore 两边 +$375，threshold 两边 +$1,120），但资金费收入太小，
   盖不住逆势持仓的价格亏损和摩擦。资金费率极端值不是可靠的反转信号。
2. **资金费率作为过滤器是有效的，但价值有限。** 它把资金费拖累砍掉
   1/3–1/2，换来 ETH 上的显著改进，但代价是错过部分突破，在 BTC/SOL/BNB
   上净收益反而下降。过滤器的净效应取决于币种，不是一致的改进。
3. **本轮 3 个策略 1 个存活：`funding_filtered_keltner` 是经过验证的
   第 4 个候选策略**（与 rsi_atr、keltner、supertrend 并列）。是否把它
   换入 c_sharpe 组合（替换肯特纳）或作为第 4 条腿加入组合，不在本轮
   决定——那是下一步的决定，本轮只报告它可作为候选。
4. **找策略到此为止。** 按立项约定，本轮是最后一次找新策略；通用指标、
   调参与资金费率三条线都已走完，继续挖的期望收益已低于成本。
